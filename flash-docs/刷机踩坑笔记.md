# YT-K606F 刷机踩坑笔记（2026-10-21 实战）

> 起点：国行 Yoga Tab 13（YT-K606F）运行 ZUI 14.0.494 / Android 12，目标是 root。
> 终点：国际版 Android 13（`S510234_231224_ROW`）+ Magisk v30.7 root，序列号/MAC/校准完好。
> 全文每条结论都是**实测**，标 ❌ 的是我踩过的坑（含走了几小时的弯路）。

---

## 一、最准确的完整流程（9 步，一次通过版）

### 前提
- PC：Windows 10/11，`C:\Program Files (x86)\Qualcomm\QPST\bin\` 下有 `QSaharaServer.exe` / `fh_loader.exe` / `QFIL.exe`
- 固件：`YT-K606F_S510234_231224_ROW`（Android 13，最后一个干净包）
  - 下载（必须带 `obs-1` 前缀，主站 404）：
    `https://mirrors-obs-1.lolinet.com/firmware/lenowow/2021/Yoga_Tab_13/YT-K606F/`
- 平板电量 ≥ 50%（EDL 不充电）

### Step 1 — 解除 Windows 对 9008 驱动的拦截 ⭐️最大拦路虎
**不是安全启动的问题，是 HVCI（内存完整性）**。管理员 PowerShell：

```powershell
bcdedit /set testsigning on
bcdedit /set hypervisorlaunchtype off
reg add "HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity" /v Enabled /t REG_DWORD /d 0 /f
```
**重启电脑**。设备管理器里 `Qualcomm HS-USB QDLoader 9008` 的 Status 必须变成 `OK`（`CM_PROB_NONE`）。

> ❌ 坑：一直以为是 Secure Boot / 驱动版本问题，试了无数驱动无效。真因是 HVCI 用 Code Integrity 拦了 2014 年的 `qcusbser.sys`。

### Step 2 — 让平板进 EDL
```bash
adb reboot edl     # 系统能起来时最可靠
```
备用：关机后 **只按住「音量加」** → 插 USB 线（**不是双键**）。

> ❌ 坑1：双键（音量加+音量减）进的是 **FFBM**，不是 EDL。FFBM 只暴露 MTP 存储，不能写分区。
> ❌ 坑2：联想 ABL 把 `fastboot oem edl` / `fastboot reboot-edl` / `fastboot reboot edl` **全部砍掉了**，fastboot 里没有任何命令能跳 EDL。
> ❌ 坑3：卡 logo 时电源键按 15 秒无效，要按更久或等耗电。

确认端口：
```powershell
Get-PnpDevice -PresentOnly | Where-Object { $_.InstanceId -like '*VID_05C6&PID_9008*' }
```

### Step 3 — 备份 fpinfo（可选但强烈建议）
`fpinfo` 含序列号/MAC/校准，**绝不能外传**。

### Step 4 — 改区域锁字节（关键！）
**位置**：`fpinfo` 分区（LUN0，起始扇区 **8712**，256 扇区 = 1 MiB），第 **0xE9** 字节。

| 值 | 含义 |
|---|---|
| `00` | unbound（卖家已解） |
| `01` | ROW（国际版） |
| `02` | **CN / ZUI（国行锁定）** |

**固件包永远不写这个分区**（`rawprogram*.xml` 里 `filename=""` 空占位，设计上保护序列号），所以**刷再多分区也不会改这个字节**。

读 → 改 → 写：
```python
# 1) 读
xml = '<read SECTOR_SIZE_IN_BYTES="4096" filename="fpinfo_orig.bin" physical_partition_number="0" label="fpinfo" start_sector="8712" num_partition_sectors="256"/>'
# 2) 0xE9 改 0x01（务必确认只改 1 字节）
# 3) 写
xml = '<program SECTOR_SIZE_IN_BYTES="4096" filename="fpinfo_patched.bin" label="fpinfo" num_partition_sectors="256" physical_partition_number="0" start_sector="8712"/>'
```

**fpinfo 布局**（来自 github.com/dobrdigital/YOGATAB13.android13.FLASH 实测）：

| 偏移 | 大小 | 内容 |
|---|---|---|
| `0x00` | 4 | 国家码 `CNXX` |
| `0x0A` | 8 | GSN |
| `0x14` | ~30 | 机型 `LenovoYT-K606F_PRC` |
| `0x32` | ~120 | 出厂 build fingerprint |
| `0xAA` | 23 | 序列号 |
| `0xC7` | 1 | 标志（CN/ROW 都是 01，**不是**区域位） |
| `0xDB` | 6 | Wi-Fi MAC |
| `0xE2` | 6 | 蓝牙 MAC |
| **`0xE9`** | **1** | **区域锁** |

### Step 5 — 刷完整包（🔥必须含 patch）

**正确命令**（同一 firehose 会话，一次性发全部 xml）：
```powershell
fh_loader.exe --port="\\.\COM9" `
  --sendxml=rawprogram_unsparse0.xml,rawprogram1.xml,rawprogram2.xml,rawprogram3.xml,rawprogram4.xml,rawprogram5.xml,patch0.xml,patch1.xml,patch2.xml,patch3.xml,patch4.xml,patch5.xml `
  --search_path=<固件目录> --memoryname=ufs --noprompt --zlpawarehost=1 `
  --setactivepartition=1 --reset
```

预期：`{All Finished Successfully}`，约 200 秒 / 34 MB/s。

> ❌ **坑（最致命，卡了 1 小时）**：漏了 `patch*.xml`。
> `patch0.xml` 关键行 `value="NUM_DISK_SECTORS-6."` 负责把 **userdata 分区大小修正成实际磁盘大小**。
> 包内 `gpt_main0.bin` 里 userdata 是**零长度占位**（1790760 → 1790759，反的）。
> 漏 patch → **userdata 分区在 fastboot `getvar all` 里根本不存在** → 系统无处挂载数据 → **永久卡 Lenovo logo**。
>
> **自检方法**：刷完进 fastboot，跑 `fastboot getvar all | grep userdata`，**没有输出 = GPT 坏了**。

### Step 6 — 开机
首次 5–10 分钟（重建应用缓存）。**超 15 分钟还是 logo = 回到 Step 5 检查 patch**。

验证：
```bash
adb shell getprop ro.build.display.id      # YT-K606F_S510234_231224_ROW
adb shell getprop ro.boot.flash.locked     # 0
```

### Step 7 — 开 USB 调试
设置 → 关于平板 → 连点「版本号」7 次 → 系统 → 开发者选项 → USB 调试。
> ⚠️ 下拉通知栏切 MTP/PTP **不会**出现 ADB 选项，ADB 与 USB 模式是两回事。

### Step 8 — Magisk root（**设备端**打补丁）
1. 装 `Magisk-v30.7.apk`
2. 推原版 boot：`adb push boot.img /sdcard/Download/`（用 `MSYS_NO_PATHCONV=1`）
3. 平板上打开 Magisk → 安装 → **选择并修补一个文件** → 选 boot.img → 开始
4. 拉回补丁：`adb pull /sdcard/Download/magisk_patched-*.img`
5. **刷前验证 DTB 未变**（见下方坑位）
6. `fastboot flash boot_a` + `fastboot flash boot_b`
7. 重启，40 秒进系统
8. 平板上 Magisk → 超级用户 → 打开 `Shell` 开关（否则 `su -c` 报 Permission denied）

验证：
```bash
adb shell /debug_ramdisk/su -c id
# uid=0(root) gid=0(root) context=u:r:magisk:s0
```

### Step 9 — 收尾
- 关测试签名（可选）：`bcdedit /set testsigning off` + HVCI 恢复 + 重启
- 别急着刷 `S510488`（已知 QFIL 加载 `contents.x` 报错 + 关机不充电）

## 二、坑位清单（按踩坑代价排序）

| # | 坑 | 真相 | 对策 |
|---|---|---|---|
| 1 | 9008 端口一直 `Status: Error` | HVCI 拦截老驱动，不是安全启动 | `testsigning on` + HVCI=0 + `hypervisorlaunchtype off` |
| 2 | 漏刷 `patch*.xml` → 卡 logo | GPT 里 userdata 是零长度占位 | 必须一次发 `rawprogram*` **+ `patch*`** |
| 3 | 双键进 EDL | 双键进的是 FFBM（只暴露 MTP） | **只按音量加** + 插线 |
| 4 | fastboot 里找 `oem edl` | 联想 ABL 砍掉了所有 EDL 跳转命令 | 只能 `adb reboot edl` 或按键 |
| 5 | Git Bash 报 `Error setting com port timeouts` | `\\.\COM9` 被 MSYS 转成 `\.COM9` | **fh_loader/QSaharaServer 必须用 PowerShell 跑** |
| 6 | `adb push` 报 `remote secure_mkdirs failed` | `/sdcard/...` 被转成 Windows 路径 | 加 `MSYS_NO_PATHCONV=1` |
| 7 | 后台刷机中断 | `Start-Process -WindowStyle Hidden` 起的进程会被回收 | 用 Python `subprocess.Popen` + `run_in_background` |
| 8 | “Magisk 改坏了 DTB” | **误判**（偏移算错） | 用 FDT 魔数 `\xd0\x0d\xfe\xed` + totalsize 定位，四块 SHA 一致 |
| 9 | 卡 logo 时长按电源无效 | 内核还活着，UI 卡死时收不到 | 进 EDL 用 `fh_loader --reset` |
| 10 | `su -c` 报 Permission denied | Magisk 授权列表没有 Shell | Magisk → 超级用户 → 打开 Shell |

## 三、区域锁的真实技术背景

**来源**：XDA 深度分析（Y700 版，联想架构通用）

1. 区域码存在 **RPMB**（Replay Protected Memory Block），由 QSEE 通过 QSEECOM 保护
2. ABL 有 `oem unlock-region` 命令，但要联想**私钥**签挑战值 → **密码学上不可破**
3. 2024 年后的新机型走这条（RPMB）→ **改不动**
4. **2021 年的 K606F 走的是 fpinfo 路** → **修改有效**（实测）

**结论**：不是所有联想平板都能破区域锁，但 K606F 可以。

## 五、这套流程的可复用性

| 机型 | 能否照搬 |
|---|---|
| 联想 2021 年前的高通平板 | ✅ fpinfo 0xE9 大概率同类 |
| 联想 2024 年后的新平板 | ❌ 走 RPMB，改不动 |
| 其他品牌 | ❌ 机制不同 |

**通用可复用的部分**：
- HVCI 拦截 9008 驱动的解法（所有高通刷机都适用）
- `patch*.xml` 修 GPT 的必要性（所有高通 rawprogram 刷机都适用）
- Git Bash 路径转换坑（所有 adb/fastboot/fh_loader 都适用）
- DTB 验证法（FDT 魔数 + totalsize，所有 boot.img 都适用）
